# Техническое задание-промт: Jarvis — локальный Android-помощник

**Скопируй весь текст от «РОЛЬ» до «КОНЕЦ ПРОМТА» и отправь ИИ-кодеру/агенту.** Пусть он работает в собственном серверном окружении с терминалом и GitHub. Не передавай ему пароли, токены или приватный ключ подписи.

## РОЛЬ

Ты — автономный senior Android-разработчик. Создай, собери, протестируй и предоставь устанавливаемый APK личного помощника **Jarvis**. Работай в своём серверном окружении: создай полноценный Git-репозиторий, исходный код, README и GitHub Actions workflow для сборки. Не ограничивайся макетом или инструкцией — доведи проект до реально собираемого APK. Если часть функций нельзя честно закончить или проверить, явно обозначь это и не имитируй готовность.

Не задавай пользователю длинную серию вопросов. Используй требования ниже; если действительно есть блокирующая неоднозначность, сначала предложи разумный безопасный default и продолжай. Не проси секреты и не помещай их в исходники.

## ЦЕЛЬ И ОБЩИЕ ОГРАНИЧЕНИЯ

Сделай приложение для Android, которое:
- устанавливается отдельным **лёгким универсальным APK** (не включай большие AI-модели в APK);
- ориентировано на Android 10+; телефон разработчика для первичной проверки — Realme RMX3706, Android 13, ARM64;
- после установки скачивает модели через экран приложения по явному нажатию пользователя. До скачивания показывает источник, лицензию и размер. Основной сценарий — кнопка «Скачать всё»; перед началом показывает общий объём и спрашивает подтверждение. Поддержи Wi‑Fi и мобильную сеть с предупреждением о расходе трафика, отмену, прогресс, повтор/докачку и понятную ошибку;
- укладывает **все скачиваемые модели вместе примерно в 2 ГБ максимум**. APK и модели — раздельно. Показывай фактический размер и не обещай точный бюджет, пока не проверил файлы;
- использует скачанные модели только локально. Текст запросов, фото, аудио, история и данные экрана не отправляются на сервер. Сеть разрешена только для первоначального скачивания моделей и явной проверки обновлений. Без скрытой телеметрии/аналитики;
- хранит историю, пользовательские настройки, аватар и модели локально. Дай очистку истории и отдельное удаление каждой модели с подтверждением;
- обрабатывает недоступность функции на конкретном телефоне graceful: отключает только неподдерживаемую функцию, объясняет причину, не блокирует остальное приложение.

Язык интерфейса — русский. Имя по умолчанию «Jarvis», его можно поменять в приложении. Иконка/имя приложения настраиваемы в пределах Android-политик. Ответ по умолчанию: короткий вывод плюс шаги; при сомнении модель сообщает о неуверенности и просит уточнить, а не выдаёт догадку за достоверный факт.

## ФУНКЦИИ

### 1. Чат и локальная модель
- Диалоговый экран с историей на устройстве, вводом текста и кнопкой очистки истории.
- Локальный движок инференса для Android; исследуй и выбери реально совместимый с NDK/ABI вариант. Предпочтительный кандидат — llama.cpp/JNI и GGUF, но сначала проверь официальные инструкции, сборку, лицензию и поддержку нужных текстовых/vision-моделей. Не добавляй фиктивную интеграцию и не называй удалённую API «локальной моделью».
- Предложенные кандидаты для проверки, не безусловный выбор: текстовая Qwen2.5-1.5B-Instruct GGUF Q4_K_M; vision-модель SmolVLM-500M-Instruct (проверить поддерживаемый формат и необходимые projector-файлы); русская малая офлайн-модель Vosk. До реализации сообщи точные названия файлов, версии/ревизии, размер, лицензию и источник. Проверь, что лицензия разрешает предполагаемое использование и распространение/загрузку. Если модели не совместимы с движком, найди проверенную альтернативу и объясни выбор.
- Всегда пинь конкретную версию/commit модели, не скачивай плавающий `main` в продакшене. Для каждого файла фиксируй ожидаемый SHA‑256 из проверенного источника/сборочной процедуры. Вычисляй SHA‑256 после загрузки и отказывайся загружать в движок при несовпадении. Никогда не придумывай хэш. Если официальный источник не публикует checksum, получи файл из закреплённой ревизии доверенным способом, зафиксируй checksum в репозитории и опиши происхождение.
- Математику по возможности обрабатывай также детерминированным проверяемым вычислителем, не выдавай результат маленькой LLM за гарантированно правильный. Для всех школьных предметов честно укажи ограничения модели.

### 2. Фото и галерея
- Пользователь может сделать фото камерой или выбрать фото через Android Photo Picker (не запрашивай полный доступ к галерее, если системный picker достаточен).
- Vision-модель по возможности описывает сцену, отвечает по снимку и пытается читать фото школьных заданий. Не обещай идеальный OCR/понимание. Показывай предупреждение/возможность поправить распознанное условие; при низкой уверенности попроси переснять/уточнить.
- Картинка обрабатывается локально. Уменьшай копию/разрешение для инференса, не меняя оригинал; контролируй память. Если vision не поддерживается или модель не скачана, остальной чат работает, UI ясно сообщает, как включить функцию.

### 3. Плавающий «Dynamic Island»
- Перемещаемый пользователем компактный плавающий островок поверх других приложений. Запрашивай `SYSTEM_ALERT_WINDOW` только по явному нажатию; объясни системный экран разрешения. Разрешение не обходить.
- Касание островка открывает/разворачивает чат; удержание начинает голосовую запись, отпускание прекращает. При отсутствии речи/ошибке распознавания разверни поле ввода текста и кнопку отправки. Когда клавиатура открыта, островок разворачивается в панель ввода.
- Обеспечь нормальный drag без случайного запуска записи; различай жест перемещения, короткое касание и долгое удержание. Поддержи позицию островка и настройку размера/видимости. Не перехватывай касания вне границ островка и не создавай обманчивые/невидимые overlay.
- Явно учитывай Android 10–14+ ограничения фонового запуска и микрофона. Запись поверх других приложений может требовать foreground service с постоянным видимым уведомлением и микрофонным индикатором. Запускай запись только после явного действия пользователя, получи runtime-разрешение RECORD_AUDIO, корректно останавливай микрофон при отпускании/ошибке/закрытии. Если ОС запрещает запуск из фона — покажи понятный fallback, не маскируй проблему и не записывай постоянно. Тестируй разрешения для всех заявленных API.

### 4. Голосовой ввод, полностью офлайн
- Удержание островка: запись → отпускание → распознавание → отправка распознанного текста в локальный чат. Пользователь видит состояние записи и распознанный текст, может отменить/исправить до отправки.
- Устройство Android может не иметь офлайн-пакета русского распознавания. Поэтому предложи скачиваемый офлайн-распознаватель (например, Vosk, только после проверки точной русской модели, лицензии и размера) либо явно покажи, что офлайн-голос недоступен. Никакого тихого перехода на облачную речь.
- Ответы отображаются текстом; добавь опциональную кнопку озвучивания через установленный на устройстве TTS. Не загружай аудио пользователя в интернет.

### 5. Аватар Jarvis
- Пользователь может переименовать помощника, выбрать изображение-превью и опционально выбрать короткий видеоаватар из локального хранилища.
- Во время генерации видео циклически показывается в островке; по завершении/ошибке возвращается статичное изображение. Видео — MP4 до 30 секунд и до 100 МБ, как запросил пользователь; проверяй формат/размер/длительность до воспроизведения, без перекодирования исходника. Поскольку 100 МБ чрезмерны для плавного overlay, предупреди о возможных задержках и предложи разумную рекомендацию по качеству/размеру, не изменяя оригинал. Используй безопасный Android document picker и scoped storage.
- Учитывай lifecycle, ориентацию, частоту кадров, закрытие плеера и освобождение памяти; при неудаче показывай фото вместо видео.

### 6. Управление другими приложениями
- Пользователь просит запускать приложения и выполнять действия на экране, включая режим работы со всеми приложениями. Для нажатий используй Android AccessibilityService только после отдельного объяснения назначения и явного ручного включения в системных настройках. Не пытайся автоматически включить его, не скрывай уведомления/индикаторы и не выдавай сервис за системный.
- Перед серией обычных нажатий показывай понятный план/предпросмотр и кнопку подтверждения; выполняй только разрешённые действия, проверяй результат каждого шага. Не придумывай координаты и не выполняй действия без явной команды пользователя. Запуск приложения можно предложить напрямую.
- Всегда требуй отдельное подтверждение перед отправкой сообщений, удалением/изменением данных, публикацией и покупками/платежами. Никогда не автоматизируй ввод паролей, PIN, кодов MFA, платёжных реквизитов, CAPTCHA, биометрические/защитные подтверждения. При таких экранах остановись и передай управление человеку. Если Accessibility API не подходит для конкретного действия, скажи об этом.
- Объясни последствия полного доступа: сервис потенциально видит доступное содержимое других окон. Обрабатывай данные экрана только локально и только в момент явно запрошенного действия; не логируй тексты/снимки экрана. Дай заметный выключатель сервиса и инструкцию отключения в системных настройках. Проверь требования Android/Google Play; не заявляй соответствие Play Store, если оно не проверено. APK можно передавать напрямую как sideload, но предупреди об источнике/разрешении установки.

## АРХИТЕКТУРА И КАЧЕСТВО

- Предложи простую поддерживаемую архитектуру и объясни решения кратко в `docs/ARCHITECTURE.md`.
- Закрепляй версии Gradle, Android Gradle Plugin, SDK, NDK и зависимостей; используй только совместимые с AndroidIDE версии для локальной альтернативной сборки, но основная сборка должна идти на сервере/GitHub Actions.
- Поддержи как минимум ARM64-v8a; если реально и без чрезмерного усложнения — armeabi-v7a для более универсального APK. Укажи фактические ABI и устройства, которые проверены. Не называй APK универсальным, если внутри только один ABI: тогда явно напиши «ARM64 APK».
- Минимизируй APK; native engine увеличивает размер, это надо измерить. Разделяй APK, загружаемые модели и пользовательские медиа.
- Обрабатывай отмену, отсутствие места, сетевой обрыв, повреждение/несовпадение checksum, смену сети, отсутствие разрешения, нехватку RAM и нехватку батареи. Не зависай на UI thread. Не делай скрытых сетевых запросов.
- Добавь автоматические unit/UI-тесты для критических состояний. Добавь тесты проверки checksum/download manager, состояния модели, UI ошибок/отмены и демонстрационный тест диалога с mock-engine. Любые неподтверждённые end-to-end сценарии на реальном телефоне пометь как «не проверено на устройстве».
- Добавь `PRIVACY.md`, список лицензий/NOTICE для приложения, native engine и каждой модели, а также понятный экран «О приложении / Приватность / Источники моделей».

## СБОРКА И ПЕРЕДАЧА APK

1. Создай репозиторий с полными исходниками, Gradle Wrapper, README на русском и инструкцией сборки в AndroidIDE/Android Studio.
2. Добавь GitHub Actions workflow, который собирает debug APK при push и вручную (workflow_dispatch), запускает тесты и публикует APK как downloadable artifact/release. Пинь GitHub Actions по безопасным версиям/commit SHA, где практически возможно; не загружай keystore/секреты в Git.
3. В первую очередь получи воспроизводимый `assembleDebug`/`assembleRelease` успешный build. Сохрани отчёты сборки, размер APK и сведения об ABI.
4. Не подписывай release приватным ключом, созданным в серверном агенте, без отдельного явного согласия владельца. Для тестовой пересылки допустим debug APK; предупреди, что APK с другой подписью не обновит установленную версию — придётся удалить старую (данные приложения могут потеряться) и установить новую. Для постоянных обновлений владелец сам создаёт и безопасно хранит keystore; GitHub Secrets — только если владелец сознательно настраивает их сам, никогда не проси прислать пароль/keystore в чат.
5. В финале дай ссылку на репозиторий, прямую ссылку на скачивание APK/artifact, точную инструкцию установки на телефон друга, проверенные функции, известные ограничения, лицензии и точные версии моделей. Если GitHub требует авторизации для artifacts, скажи это; предложи GitHub Release для файла, но не публикуй модели/секреты без проверки прав.
6. Если сборка провалилась, не объявляй APK готовым: приведи существенную ошибку лога, исправь её и повторяй сборку до результата или конкретного блокера.

## КРИТЕРИИ ПРИЁМКИ

- Чистый checkout успешно собирается на CI; workflow прикладывает устанавливаемый подписанный тестовый APK.
- APK мал относительно моделей; модели не встроены в APK и скачиваются только после согласия пользователя.
- Проверены размеры, лицензии, закреплённые ревизии и SHA‑256 всех модельных файлов. Ошибочный хэш не позволяет инференс.
- Чат действительно выполняет inference локально в авиарежиме после загрузки модели (проверь тестом, не только по коду); фото и русский voice также проверены офлайн либо честно помечены как неподтверждённые/неподдерживаемые.
- Overlay можно переместить; касание/удержание/перетаскивание различаются; аудиозапись видимая, только по удержанию, и прекращается при отпускании.
- Пользовательские имя, фото и MP4-аватар настраиваются; видео показывается только во время генерации и затем возвращается фото.
- Accessibility выключен по умолчанию, включается только в настройках Android по инициативе пользователя; действия имеют предпросмотр и опасные операции требуют отдельного подтверждения.
- Приложение остаётся локальным, не отправляет prompts/media/screen text наружу; сетевые endpoints перечислены в документации.
- README содержит реальные шаги, тестовые результаты, размер APK, известные ограничения, модели и лицензии. Не заявляй функцию, которую не проверил.
